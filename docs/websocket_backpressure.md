# WebSocket 输出背压

同步 `sendText`/`sendBinary` 原来可以让一个慢客户端的写入 Fiber 长时间等待。现在 WebSocket 帧在构造前先预留发送字节，默认全进程预算 64 MiB；同一会话只允许一个写入进行中。预算不足时抛出 `ENOBUFS`，连接处理器结束并关闭该连接。单消息仍受 1 MiB 默认上限约束。写入使用默认 2 秒总截止时间，超时抛出 `ETIMEDOUT`，释放预算并结束连接。等待 socket 可写时不持有全局锁。

`OutboundBudget` 可注入较小预算做隔离测试；`/metrics` 暴露当前预留字节、预算上限和累计拒绝数。测试覆盖预算竞争、异常释放，以及不读取 socket 的慢消费者写超时；另一个 Fiber 在慢写等待期间仍运行。

当前服务端仍是同步逐条发送，没有广播排队。预算仅限制已开始构造/发送的帧；若未来增加异步广播队列，该队列必须在入队前预留同一个预算，并在丢弃、断连或取消时归还。当前超时会断开慢连接，不做消息持久化，也不保证交付。排空过程尚未实现 WebSocket 1001 Close 握手。
